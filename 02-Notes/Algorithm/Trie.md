# Trie

## 核心思想

高效地存储和查找字符串集合的数据结构，**整数也能存**

**Map 擅长“这个词有没有”，Trie 擅长“这个前缀下面有什么”。**

**序列化 + 前缀 + 逐层选择** 
  如果一个对象能表示成一串元素，并且问题需要从前往后逐位决策、前面的选择会限制后面的选择，就可以考虑 Trie。

## 关键理解

每个结点的编号是二维数组的第一维，然后让p从上一个结点每次跳转到这个编号。也就是p每次跳到第二维，然后成为第一维。son数组第二维存的信息就是跳转信息。

**算法竞赛里存树**，常见有两种思路：

1. **存“边”**：用邻接表
    
    - `vector<int> g[N]`
    - 或链式前向星 `head / to / nxt`
    
    这种最通用，尤其是题目给你的是 `u v` 表示一条无向边时。
    

```
vector<int> g[N];

g[u].push_back(v);
g[v].push_back(u);
```

2. **存“父子关系”**：用 `son` / `child` 数组  
    前提是父子关系已经确定。

```
vector<int> son[N];

son[u].push_back(v); // u 是父亲，v 是儿子
```

比如：

```
    1
   / \
  2   3
     / \
    4   5
```

那么：

```
son[1] = {2, 3};
son[3] = {4, 5};
```

不过有一个很重要的点：**`son` 并不是一种特殊的数据结构，本质上它还是邻接表。**

区别只是：

```
g[u]   ：存 u 的所有邻居
son[u] ：只存 u 的儿子
```

例如上面那棵树：

```
g[3] = {1, 4, 5};   // 1 是父亲，4、5 是儿子
son[3] = {4, 5};     // 只存儿子
```

所以竞赛里更建议你建立这个思维：

> **无根树 → 通常双向邻接表存边。**  
> **有根树 → 可以仍然用邻接表，也可以确定父子关系后只存 `son`。**
