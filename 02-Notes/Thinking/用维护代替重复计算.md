**思考方式：**

> **盯住“内层循环指针移动一格”以后，旧答案和新答案之间有什么关系。**

有两个操作，如果其中一个操作每次操作时都要循环赋值一次（很耗时间），可以一直维护这个操作：另开一个数组。当操作别的操作时也维护这个数组。然后遇到这个耗时操作时就不用在赋值了，直接聚焦在另一个数组就行了

## chatgpt

可以把你刚才遇到的两类题统一总结成一个核心思想：

> **用“维护信息”代替“重复计算”。**

第一类是二重循环：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j < i; j++) {
        ...
    }
}
```

优化时先问：

> 内层循环到底在统计什么？

然后改成：

```cpp
for (int i = 1; i <= n; i++) {
    query();       // 直接查询已经维护的信息
    update(a[i]);  // 把当前元素加入维护的信息
}
```

常见对应关系：

- 前缀和、总和 → 维护 `sum`
    
- 出现次数 → 哈希表
    
- 前面小于/大于某值的数量 → 树状数组
    
- 最近更大/更小元素 → 单调栈
    
- 连续区间问题 → 双指针 / 滑动窗口
    

第二类是多次操作：

```text
修改 update
查询 query
修改 update
查询 query
...
```

如果原来是：

```text
update：O(1)
query ：O(n)
```

而查询很多次，就可以考虑：

> **在 update 的时候顺便维护 query 需要的信息。**

例如维护数组总和：

```cpp
sum -= a[x];
sum += v;
a[x] = v;
```

之后查询总和直接：

```cpp
cout << sum;
```

于是查询从 (O(n)) 变成 (O(1))。

更一般地，算法题里经常是在平衡：

```text
修改成本  ↔  查询成本
```

比如区间和：

|方法|修改|查询|
|---|--:|--:|
|普通数组|(O(1))|(O(n))|
|前缀和|(O(n))|(O(1))|
|树状数组|(O(\log n))|(O(\log n))|

所以以后看到超时的循环，可以形成一个固定思考流程：

1. **慢在哪里？** 哪个循环被重复执行很多次？
    
2. **循环算的是什么信息？**
    
3. **这个信息能不能提前保存？**
    
4. **数据变化时，能不能只更新变化的部分？**
    
5. **如果完全维护太贵，能不能用数据结构做到 (O(\log n))？**
    

一句话记住：

> **能增量维护，就不要每次从头计算。**

而你刚才说的“二重循环优化”和“两个操作中提前维护昂贵操作”，本质上就是同一种算法思维。
