# Falling Concrete：这道题的完整收获总结

## 1. 第一层：先找到题目的不变量

原数组中第 $i$ 个元素定义

$$
b_i=a_i-i
$$

一次操作里，无论某个元素是被搬到前面，还是因为别人被搬走而向后移动，它的：

$$
\boxed{\text{高度}-\text{位置}}
$$

始终不变。

所以每个元素真正不会改变的“身份”是：

$$
b_i=a_i-i
$$

最终如果存在一段长度为 $k$ 的平坦区间，假设高度都是 $H$，位置依次是：

$$
L,L+1,\dots,L+k-1
$$

那么这一段中元素对应的不变量一定是：

$$
H-L,\ H-L-1,\dots,H-L-(k-1)
$$

也就是 $k$ 个连续整数。

因此原题最终被转化成：

$$
\boxed{\text{在所有 }a_i-i\text{ 中，求最长连续整数段}}
$$

重复值没有贡献，所以可以排序去重。

这一步是整道题最重要的“建模”。

---

# 2. 转化完成以后，最自然的是二重暴力

假设排序去重后的数组为：

```text
1 2 3 4 8 9 10
```

现在问题只是：

> 最长的连续整数段有多长？

最朴素的想法自然是枚举一个端点，再枚举另一个端点。

而这里其实有两个完全对称的视角。

---

## 3. 暴力视角一：枚举左端点，再向右扫

写成：

```cpp
for (int l = 1; l <= m; l++) {
    for (int r = l + 1; r <= m; r++) {
        if (b[r] == b[r - 1] + 1)
            ...
        else
            break;
    }
}
```

含义是：

> 固定起点 $l$，向右寻找这一段最远能够到达的位置 $r$。

例如：

```text
1 2 3 4 | 8 9 10
```

第一次：

```text
l = 1
r 一直走到 4
```

下一次：

```text
l = 2
```

如果重新让 `r` 从 `3` 开始扫，其实大量工作被重复做了。

---

# 4. 这时候用你笔记里的核心问题

你之前笔记里总结得非常好：

> **盯住“内层循环指针移动一格”以后，旧答案和新答案之间有什么关系。** 

更一般地可以升级成：

> $$
> \boxed{\text{外层状态变化以后，上一轮内层循环的进度或结果能不能复用？}}
> $$

这比单纯说“优化二重循环”更接近本质。

你的原笔记本身也是在强调：

> **用“维护信息”代替“重复计算”。** 

---

# 5. 对视角一应用这个问题：右端点需要回来吗？

上一轮：

```text
l = 1
```

我们已经知道：

```text
[1, 2, 3, 4]
```

是连续的，最远右端点是 `4`。

现在左端点变成：

```text
l = 2
```

那么：

```text
[2, 3, 4]
```

显然仍然连续。

所以：

$$
\boxed{\text{上一轮得到的右端点 }r\text{ 仍然有效}}
$$

没必要让 `r` 回头。

于是：

```cpp
int r = 1;

for (int l = 1; l <= m; l++) {
    while (r + 1 <= m && b[r + 1] == b[r] + 1)
        r++;

    res = max(res, r - l + 1);
}
```

这里最关键的是：

```text
l 向右走
r 只向右走，不回头
```

这就是典型的双指针。

---

# 6. 所以双指针到底是什么？

以前容易把双指针理解成：

> “代码里有两个下标。”

现在可以理解得更本质一些：

$$
\boxed{\text{双指针 = 用一个指针保存原内层循环已经扫描到哪里}}
$$

也就是说：

```cpp
int r;
```

虽然叫“右指针”，但从更抽象的角度看：

$$
\boxed{r\text{ 本质上就是一个状态变量}}
$$

它保存了：

> 上一轮内层循环已经得到的进度。

所以双指针其实正是“维护代替重新计算”的一种具体表现。

---

# 7. 但这道题还能继续发现：连很多左端点都没必要枚举

如果已经发现：

```text
1 2 3 4
```

是一整个连续段，那么：

```text
从1开始 → 长度4
从2开始 → 长度3
从3开始 → 长度2
从4开始 → 长度1
```

所以一旦整段已经确定：

```text
[1,4]
```

再枚举 `2、3、4` 作为起点没有意义。

因此甚至可以直接：

```text
处理完这一整段
↓
直接跳到下一段
```

也就是：

```cpp
int l = 1;

while (l <= m) {
    int r = l;

    while (r + 1 <= m && b[r + 1] == b[r] + 1)
        r++;

    res = max(res, r - l + 1);

    l = r + 1;
}
```

这是在双指针之后又利用了更强的题目性质：

> 同一连续段内部，后面的左端点不可能得到更长答案。

---

# 8. 现在换第二个完全对称的暴力视角

前面是：

```text
枚举左端点
→ 向右扫
```

其实还可以：

```text
枚举右端点
→ 向左扫
```

暴力：

```cpp
for (int r = 1; r <= m; r++) {
    for (int l = r; l >= 1; l--) {
        ...
    }
}
```

含义是：

> 对于每一个右端点 $r$，重新向左找“以 $r$ 结尾的最长连续段”。

---

# 9. 再问同一句话

右端点从：

$$
r-1
$$

变成：

$$
r
$$

以后，

> 上一轮内层向左扫描得到的结果，能不能复用？

当然可以。

假设上一轮已经知道：

```text
以 r-1 结尾的最长连续段长度 = cnt
```

现在新增一个 `b[r]`。

如果：

```cpp
b[r] == b[r - 1] + 1
```

说明新元素可以接在原来连续段后面：

$$
cnt\leftarrow cnt+1
$$

否则原来的段无法继续：

$$
cnt\leftarrow1
$$

于是得到：

```cpp
int res = 1, cnt = 1;

for (int r = 2; r <= m; r++) {
    if (b[r] == b[r - 1] + 1)
        cnt++;
    else
        cnt = 1;

    res = max(res, cnt);
}
```

这时候内层循环彻底消失了。

---

# 10. 两种优化终于统一了

这两个视角表面不一样：

### 左端点视角

原暴力：

```text
枚举 l
→ 每次重新向右扫 r
```

优化后：

```text
枚举 l
→ 保存上一轮的 r
→ r 不回头
```

维护的是：

$$
\boxed{\text{内层扫描的“进度”}}
$$

所以得到双指针。

---

### 右端点视角

原暴力：

```text
枚举 r
→ 每次重新向左扫 l
```

优化后：

```text
枚举 r
→ 保存上一轮向左扫描得到的长度 cnt
```

维护的是：

$$
\boxed{\text{内层扫描的“结果”}}
$$

所以得到 `cnt` 状态维护。

---

于是可以统一成：

$$
\boxed{
\text{二重循环优化的核心，不是一定维护内层指针，而是复用内层循环上一次做过的工作。}
}
$$

这个“工作”可以表现为：

```text
扫描到哪里       → 指针
算出了多长       → cnt
算出了多少和     → sum
某个元素出现几次 → map / cnt[]
当前区间的信息   → 滑动窗口状态
某个更复杂结果   → 数据结构
```

你原笔记里其实已经列出了很多这样的对应关系：总和、出现次数、树状数组、单调栈、双指针，本质上都是“维护信息，避免重新计算”。

# 11. 为什么 `cnt` 这个版本又很像 DP？

因为如果正式定义：

$$
dp[r]=\text{以 }r\text{ 为右端点的最长连续段长度}
$$

那么：

$$
dp[r]=
\begin{cases}
dp[r-1]+1,& b[r]=b[r-1]+1\\
1,&\text{否则}
\end{cases}
$$

答案：

$$
ans=\max dp[r]
$$

这就是非常标准的状态转移。

只不过：

$$
dp[r]
$$

只依赖：

$$
dp[r-1]
$$

所以根本不需要整个 `dp[]` 数组。

只需要一个：

```cpp
cnt
```

保存上一轮状态即可。

于是：

```cpp
if (b[r] == b[r - 1] + 1)
    cnt++;
else
    cnt = 1;
```

可以看成：

$$
\boxed{\text{DP 的状态压缩}}
$$

所以你觉得它有 DP 味道，是完全正确的。

---

# 12. 双指针和 DP 为什么会让人觉得很像？

因为站在更高层看，它们都在做同一件事情：

$$
\boxed{\text{复用已经计算出来的信息}}
$$

双指针更关注：

> **上一次扫描到了哪里？**

DP 更关注：

> **上一个状态算出了什么？**

例如这题：

```text
双指针：
保存 r
= 上一次内层循环走到哪里
```

而：

```text
cnt / DP：
保存 cnt
= 上一次内层循环算出了多长
```

所以它们不是同一种具体算法，但它们背后的“避免重复计算”思想是相通的。

# 13. 最重要的思维升级

你原来可能会问：

> “这个二重循环怎么优化？”

现在可以把问题问得更具体：

> **外层循环变化以后，内层循环上一次做过的工作，有哪些还能继续用？**

再进一步拆成两个问题：

```text
上一次内层循环跑到哪里？
→ 能不能继续从那里跑？
→ 双指针 / 单调指针

上一次内层循环算出了什么？
→ 能不能由旧结果快速推出新结果？
→ 状态维护 / DP / 增量更新
```

这就是这道题最大的算法收获。

# 14. 以后看到二重循环，可以形成这样的固定思考流程

先别急着想数据结构。

看到：

```cpp
for (...) {
    for (...) {
        ...
    }
}
```

先问：

> **外层改变以后，内层真的需要从头来一遍吗？**

然后观察：

```text
① 内层指针的位置能不能保留？
   → 双指针 / 滑窗 / 单调扫描

② 内层循环算出来的结果能不能保留？
   → cnt / sum / hash / DP

③ 旧状态到新状态，只改变了什么？
   → 只更新变化部分

④ 有没有一些外层状态本身也根本不用枚举？
   → 整段跳过 / 剪掉冗余状态
```

这其实正好把你笔记最后的总结扩展了一层。你原来的核心是：

> **能增量维护，就不要每次从头计算。** 

现在可以升级成：

$$
\boxed{
\text{外层状态变化以后，优先考虑复用上一轮内层循环的“进度”或“结果”，而不是重新计算。}
}
$$

# 15. 回到这道题，最终为什么推荐 `for + cnt`

虽然我们绕了这么多思路，但最终代码反而非常简单：

```cpp
sort(b + 1, b + n + 1);
int m = unique(b + 1, b + n + 1) - (b + 1);

int res = 1, cnt = 1;

for (int i = 2; i <= m; i++) {
    if (b[i] == b[i - 1] + 1)
        cnt++;
    else
        cnt = 1;

    res = max(res, cnt);
}
```

因为这道题最后发现：

> 我根本不关心左端点具体在哪里，只关心当前连续段有多长。

本来双指针可以维护：

$$
[l,r]
$$

但是我们只需要：

$$
r-l+1
$$

所以直接维护：

```cpp
cnt
```

就够了。

这就是：

$$
\boxed{\text{在正确算法基础上，继续压缩“不必要的状态”}}
$$

# 16. 这道题完整的思维链

最终可以记成：

$$
\boxed{
\text{操作题}
\rightarrow
\text{找不变量 }a_i-i
\rightarrow
\text{转化成最长连续整数段}
}
$$

然后：

$$
\boxed{
\text{二重暴力}
\rightarrow
\text{思考内层工作能否复用}
}
$$

从左端点视角：

$$
\boxed{
\text{维护右端点的扫描进度}
\rightarrow
\text{双指针}
}
$$

从右端点视角：

$$
\boxed{
\text{维护向左扫描得到的结果}
\rightarrow
cnt
\rightarrow
\text{状态递推 / DP 味道}
}
$$

最后：

$$
\boxed{
\text{发现只需要长度}
\rightarrow
\text{把左端点状态也省掉}
\rightarrow
for+cnt
}
$$

> **看到二重循环，不要只想着怎么少循环几次；要问：外层状态变化以后，上一轮内层循环的“进度”或“结果”还能不能复用。复用进度，常常得到双指针；复用结果，常常得到状态维护或 DP。**

而这又正好是你原笔记那句话的进一步展开：

> **能增量维护，就不要每次从头计算。**
