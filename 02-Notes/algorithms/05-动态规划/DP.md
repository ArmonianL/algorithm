# DP

## 核心思想

DP 本质上就是把一个大问题拆成很多小问题，用已经解决的小问题去更新更大的问题，因此天然存在“过去到未来”的先后关系。

DP 的关键，是把“对未来影响相同”的情况合并起来。我们并不关心过去具体是怎么走到当前状态的，因为过去的情况可能非常多；只要这些情况对未来产生的影响相同，就可以用同一个状态来表示。

所以做 DP 最重要的就是两个问题：

1. **怎么表示状态**：当前状态要能概括所有对未来有用的信息，也就是只保留“过去对未来的影响”，不记录无关的历史过程。
    
2. **怎么计算状态**：也就是研究状态之间如何转移，当前状态可以由哪些之前的状态转移过来。换个角度说，就是研究当前这个集合可以如何按照不同的来源划分。
    

因此，DP 说到底最核心的关键词就是：

**状态和转移。**

状态负责把复杂的历史合并，转移负责描述不同状态之间的关系。

> 2026-09-22

1. **DP 的本质不是“过去推未来”，而是“状态 + 依赖关系”。**
    
2. **当前状态依赖谁，谁就必须先被算出来。**
    
3. **过去 / 未来只是你定义 `dp` 状态后的视角，不是固定的。**
    
4. **Top-down（递归 + 记忆化）**：先求大问题，再递归求它依赖的子问题。
    
5. **Bottom-up（for 循环）**：先把最基础、被依赖的状态算好，再逐步推出目标状态。
    
6. **同一道题可以换状态定义或把路径反过来看，因此“过去”和“未来”可以互换。**
    

滑雪题一句话总结：

> 实际滑雪是 **高 → 低**，但如果 `dp[x]` 表示“从 x 出发还能滑多远”，那么 `dp[高]` 依赖 `dp[低]`，所以填表要 **低 → 高**；递归则可以直接从高处往低处找。

最核心的一句：

> **DP 不关心现实中的前后，只关心：算我之前，谁必须先有答案。**

## 适用场景


$$
DP = 状态 + 转移
$$

你可以把判断思路压缩成两句话：

- **历史情况很多、组合爆炸** → 想“状态怎么表示”，也就是把对未来影响相同的历史合并起来。
- **问题有阶段、有先后关系** → 想“状态怎么转移”，也就是当前状态如何由之前的状态得到。

再进一步，其实就是：

状态负责合并历史，转移负责连接阶段
