对，算法里“树怎么放进内存”其实有几种非常经典的方式。你现在接触到的**堆数组、Trie数组**，只是其中两种。

最常见可以理解成 **4 类**：

### 1. 数组直接表示树的位置

典型就是**堆**。

```text
        1
      /   \
     2     3
    / \   / \
   4   5 6   7
```

数组：

```cpp
heap[1] = 10;
heap[2] = 20;
heap[3] = 30;
```

靠下标关系确定结构：

```cpp
parent(i) = i / 2
left(i)   = 2 * i
right(i)  = 2 * i + 1
```

这种方式要求树的结构比较特殊，比如**完全二叉树**。

---

### 2. 节点 + 指针 / 引用

最直观的树结构。

```cpp
struct Node {
    int val;
    Node* left;
    Node* right;
};
```

内存里每个节点存：

```text
值
左儿子地址
右儿子地址
```

结构完全由指针连接起来。

**二叉搜索树、普通二叉树、AVL、红黑树**等经常这样表示。

你可以把它理解成：

> 节点自己知道“我的孩子是谁”。

---

### 3. 数组存节点 + 数组存关系

这就是你刚才说的 **Trie** 的典型情况。

```cpp
int son[N][26];
```

比如：

```cpp
son[1]['a'] = 2;
```

意思是：

```text
节点1 --a--> 节点2
```

这里：

- `1`、`2` 是节点编号
    
- `son` 数组保存节点之间的关系
    

所以实际上是：

> **把指针换成了整数编号。**

这在算法竞赛里非常常见，因为比指针更方便管理，也通常更快。

Trie、图、某些树形结构都会这么做。

---

### 4. 边表 / 邻接表

这个特别重要。

实际上**树本质上就是一种特殊的图**，所以完全可以用图的方式存。

例如：

```text
        1
      /   \
     2     3
    / \
   4   5
```

可以存成：

```cpp
vector<int> g[N];

g[1] = {2, 3};
g[2] = {1, 4, 5};
g[3] = {1};
g[4] = {2};
g[5] = {2};
```

这里不再强调“左儿子、右儿子”，而是只记录：

> **这个节点和哪些节点相连。**

这也是为什么很多算法题里，题目说“给你一棵树”，最后写出来却是：

```cpp
vector<int> g[N];
```

因为算法上把它当成**无环连通图**处理。

---

## 你可以建立一个总框架

其实你以后看到树的代码，可以先问自己：

> **“这个代码到底是在存节点，还是在存节点之间的关系？”**

大致就是：

```text
树
│
├── ① 下标本身描述结构
│      └── 堆
│
├── ② 节点里面存指针
│      └── 普通二叉树、BST、AVL...
│
├── ③ 节点编号 + 数组存关系
│      └── Trie 等
│
└── ④ 直接存边
       └── 邻接表 / 链式前向星
```

其中 **②、③、④ 本质上非常接近**：

```text
指针：
node.left = 某个节点地址

数组编号：
son[node][c] = 某个节点编号

邻接表：
g[node].push_back(某个节点编号)
```

它们其实都是在回答同一个问题：

> **“从节点 u，怎么找到和它相连的节点 v？”**

真正特殊的是**堆**：

> 堆不需要额外记录“谁和谁相连”，因为**节点编号本身就把连接关系编码进去了**。

所以你现在把“**存值**”和“**存结构**”这两个概念区分开，后面学并查集、图、线段树、树状数组、哈夫曼树时会清楚很多。
